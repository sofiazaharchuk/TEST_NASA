# Outpost Academy - тренажер юного астронавта

Безкоштовна браузерна гра для дітей **7-12 років**. Ти керуєш маленькою базою на Місяці: щодня отримуєш кілька **блоків енергії** і вирішуєш, як розподілити їх між повітрям, щитом, їжею та водою. Справжні дані NASA про спалахи на Сонці впливають на силу бурі, а кожну помилку гра пояснює в «ланцюжку причин», щоб дитина бачила, що до чого.

Створено для **NASA Space Apps Challenge 2026**: «Build a Junior Astronaut Mission Trainer». Повна англомовна версія: [README.md](README.md).

## 1. Швидкий старт

Потрібні **Node.js 22.6+** і npm.

```bash
npm install
cp .env.example .env     # впиши безкоштовний ключ NASA (https://api.nasa.gov)
npm run photos           # завантажити справжні фото NASA (потрібен інтернет)
npm run archive          # зберегти справжні спалахи для офлайну (інтернет + ключ)
npm run dev              # http://localhost:5173
```

| Команда | Що робить |
|---|---|
| `npm run dev` | сервер розробки |
| `npm test` | тести симуляції, логіки, даних NASA і контенту (без браузера) |
| `npm run build` | перевірка типів + збірка в `dist/` |
| `npm run check` | `test` + `build` (виконувати перед кожним пушем) |

**Оновлюєш із zip?** Не затирай свої дані: `unzip -o новий.zip -x 'outpost-academy/src/data/photos.json' 'outpost-academy/src/data/donkiArchive.json'`.

## 2. Технологічний стек

React 18 + TypeScript (інтерфейс), Vite 5 (збірка), Tailwind CSS 3 (стилі), Zustand (стан, зберігається в `localStorage`), Framer Motion і чисті CSS-анімації, lucide-react (іконки), i18next (переклади), WebAudio (звуки без файлів), NASA DONKI і NASA Image Library (дані), тести на чистому Node. Бекенду немає, акаунтів немає: профіль зберігається лише на пристрої.

## 3. Структура

```
src/sim/        чиста симуляція (engine.ts: playDay, blocksToday, stars)  <- серце гри
src/game/       resume.ts (продовження гри), logic.ts (допоміжні функції без UI), decisions.ts (рішення, питання)
src/data/       levels.ts (рівні як ДАНІ), sources.ts (джерела фактів), themes.ts, photos.json
src/nasa/       donki.ts (завантаження космічної погоди з кешем і запасними джерелами)
src/store.ts    Zustand: екрани, налаштування, прогрес, поточна гра
src/screens/    Start, Levels, Intro, Game, Debrief, Settings, SpaceWeather
src/ui/         ResourceCard, CoPilot, Photo, WeatherFx, MiniGames ...
src/i18n/       en, uk (повні), es fr de pl pt tr ar hi (beta)
tests/  tools/  тести і скрипти завантаження фото/архіву
```

**Правило 1:** `src/sim` і `game/logic.ts` лишаються чистими (без React і `window`), тому їх легко тестувати. **Правило 2:** жодних текстів у коді, лише ключі `t("...")` з `src/i18n/*.json`.

## 4. Як працює гра

**Потік екранів:** Start -> Levels -> Intro -> Game -> Debrief -> Levels (Settings відкривається звідусіль).

**Один день у грі:**
1. База отримує блоки: дохід дня (удвічі менше в пилову бурю) + батарея + бонуси.
2. Гравець розподіляє блоки між машинами (+/-) і вмикає дії.
3. За бажанням: щоденна мінігра (виграш = +1 блок, програш без штрафу).
4. «Завершити день» -> `playDay()` -> звіт дня з поясненням.
5. Далі рішення від Mission Control (парні дні) або наукове питання (непарні, з 3-го дня).
6. Після останнього дня або втрати всіх сердець показується Debrief із зірками та ланцюжком причин.

**Правила симуляції** (`src/sim/engine.ts`, функція чиста: повертає новий стан):
- Повітря: потрібно 2 блоки, дає +5; за кожен бракуючий блок -12; нуль = мінус серце.
- Щит: +15 за блок. Їжа: -8 щодня, +10 за блок. Вода: -6 щодня, +8 за блок.
- Метеорит: щит -20. Сонячна буря: щит >= `hi` без втрат, нижче `lo` -2 серця, між ними -1. Пороги залежать від справжньої космічної погоди: сильна `[85,55]`, середня `[70,40]`, спокійна `[55,25]`.
- Зірки: Безпека (серця), Розумність (змарнована енергія), Цікавість (наука).

**Дії:** наукова прогулянка (1 блок + 10 повітря, +1 наука); розвідувальний дрон (2 блоки, без повітря, +1 наука); зв'язок із Землею (1 блок, +8 найслабшій системі); очищення панелей (1 блок + 8 повітря, +2 блоки завтра); відпочинок (1 блок, +1 серце); навчання укриттю (у дні бурі, -1 втрата сердець).

**Рівні** лежать у `src/data/levels.ts` як дані: 1 «Перший день», 2 «Довга ніч», 3 «Стеж за бурею», 4 «Зелені пальці» (з'являється їжа), 5 «Базі потрібна вода».

**Дані NASA** (`src/nasa/donki.ts`): свіжий кеш -> живий запит DONKI (8 с) -> старий кеш -> завантажений архів (`npm run archive`) -> вбудований список відомих спалахів -> «немає даних». Гра завжди чесно показує джерело. Найсильніший клас спалаху стає «погодою» гри.

**Фото:** `npm run photos` завантажує по одному фото NASA на тему з кредитами. Якщо `photos.json` порожній, `Photo.tsx` шукає `public/photos/<тема>.jpg|png`. Фото і голоси людей до 18 років у поданні використовувати не можна.

**Розташування (екран гри):** порядок погляду продуманий: 1) тонка панель місії (рівень, день, серця) -> 2) велике фото NASA з круглими індикаторами (щит, повітря, їжа, вода) -> 3) ОДНА виділена підказка «Зроби зараз» -> 4) цілі місії маленькими мітками. Праворуч: блоки енергії -> машини бази -> додаткові дії. Знизу завжди видно кількість блоків і велику кнопку «Завершити день». На телефоні все в одну колонку в тому ж порядку.

**Нагороди й додатки:** наліпки (виводяться з прогресу), сертифікат «Юний астронавт» (малюється на canvas і зберігається або надсилається як **PNG**, працює на телефонах і у вбудованих браузерах; друк/PDF лишається додатковою кнопкою), «Повтор справжньої бурі NASA» (з 3-го рівня), картки «Чи знаєш ти?» із фото й джерелом.

**Анімації:** переходи екранів, поява карток, погодні ефекти над фото (частинки бурі + кільце щита, пил, метеори, нічне затемнення), конфеті при перемозі, блиск кнопок, серця, що б'ються. Усе вимикається в налаштуваннях («Менше руху») і системним `prefers-reduced-motion`.

## 5. Адаптивність і доступність

Телефон < 640 px: одна колонка, компактні мітки; планшет: 2 колонки карток; ноутбук / iPad в альбомній орієнтації (`lg`+): екран гри у **дві колонки** (фото зі сценою зліва, керування справа), `xl`: 3 картки рівнів у ряд. Підтримані дуже малі телефони (320 px), безпечні зони iPhone, `100dvh`, поля вводу >= 16 px (без авто-збільшення), hover лише на пристроях із мишею, `backdrop-blur` лише від `md`. Великі зони дотику, видимий фокус, `aria-live`, колір ніколи не єдиний сигнал. Налаштування: великий текст, легкий шрифт, менше руху, озвучення, звук, режим «Грати разом» для дорослих.

**Продуктивність:** ліниве завантаження екранів і мов, окремі чанки (`react`, `motion`, `i18n`, `icons`), анімації лише через transform/opacity.

## 5б. Світла і темна тема

Темна тема за замовчуванням (оригінальний дизайн). Світла вмикається кнопкою Сонце/Місяць у шапці або в Налаштуваннях -> Тема; вибір зберігається і застосовується ще до першого малювання сторінки (без блимання). Реалізація: `<html data-theme="light">` + `src/styles/light.css`, який перевизначає «темні» класи Tailwind. **Правило:** контейнер з фото під білим текстом має клас `on-photo`: він лишається темним в обох темах. Новий колірний клас, що працює тільки на темному, додайте до списку в `light.css`.

## 5в. Стабільність (прочитайте перед деплоєм)

- **ErrorBoundary:** якщо екран «падає», гравець бачить дружню сторінку з кнопкою «До місій», а не порожній фон. Технічне повідомлення є у згорнутому блоці для звітів про помилку.
- **Застарілі файли після редеплою** (`lib/resilience.ts`): стара відкрита вкладка просить старі файли з хешами, яких уже немає. Лінивим екранам додано повтор і одне безпечне перезавантаження. Саме це спричиняло «усе зникає, лишається тільки фон» на Vercel.
- **Автопереклад браузера ламає React.** Chrome/Google Translate переписують текст сторінки, і React кидає помилку `insertBefore`, тож гравець бачить сторінку помилки. Виправлено атрибутом `translate="no"` + `<meta name="google" content="notranslate">` в `index.html` і захистом у `main.tsx`. У грі власні переклади.
- **Старі пристрої:** не використовуйте `structuredClone` та інші нові API без запасного варіанта.
- **Продовження гри:** незавершений рівень зберігається в `localStorage` і відновлюється після оновлення сторінки. `game/resume.ts` перевіряє дані й відкидає пошкоджені або від старої версії.
- `vercel.json` задає кеш: `index.html` без кешу, `/assets/*` назавжди.

## 6. Як розширювати

| Що додати | Як |
|---|---|
| Рівень | Об'єкт у `LEVELS` + тексти `levels.<id>` в en/uk + тема в `themes.ts` (код не потрібен) |
| Подію | `Ev` у `sim/types.ts`, обробка в `playDay`, тексти `chain.<key>`, гілка в `WeatherFx`, тест |
| Дію | Поле в `Move` і `Acts`, вартість у `used()` і `engine.ts`, перемикач у `Game.tsx`, тексти, тест |
| Рішення / питання | `DECISIONS` / `QUIZ` у `game/decisions.ts` + тексти; `npm test` перевірить, що кожен варіант щось дає і щось коштує |
| Мінігру | Компонент у `ui/MiniGames.tsx`, тип `Mini` у `store.ts`, тексти |
| Мову | `xx.json`, запис у `languages.ts` і в `LAZY` (`i18n/index.ts`) |
| Факт NASA | Спершу джерело в `data/sources.ts`, потім посилання на його id |

## 7. Тестування

`npm test` без браузера перевіряє симуляцію, логіку, завантаження даних NASA (з підробним `fetch`) і контент (переклади, компроміси рішень, джерела). Для інтерфейсу автотестів поки немає: перед релізом пройдіть вручну всі рівні, рішення, питання, мінігру та Debrief на ширині 320 px, на планшеті й на ноутбуці, із «Менше руху» і без.

## 8. Деплой і безпека

`npm run build` -> `dist/` на Vercel / Netlify / GitHub Pages. **GitHub Pages:** `.github/workflows/deploy.yml` збирає і публікує гру при кожному пуші в `main`. Разова настройка: Settings -> Pages -> Source = **GitHub Actions** (репозиторій має бути публічним на безкоштовному плані). Гра буде за адресою `https://<користувач>.github.io/<репозиторій>/`. Ключ NASA додайте як Actions secret з назвою `VITE_NASA_API_KEY`. Перед публікацією запускається `npm test`.

Змінна `VITE_NASA_API_KEY` потрапляє в публічний JS: використовуйте безкоштовний ключ, який можна змінити, або serverless-проксі. Файл `.env` ніколи не комітьте.

## 9. Правила хакатону

- Space Apps забороняє починати роботу над челенджем до хакатону (14-15 листопада 2026). Ця підготовка велася **з дозволу організаторів: зберігайте їхнє письмове підтвердження** і вкажіть це в поданні.
- Вкажіть використання ШІ (Claude), як вимагають правила.
- Перелічіть дані NASA: DONKI, NASA Image and Video Library, BVAD, MOXIE та інші з `src/data/sources.ts`. Факти з `verify: true` перевірте перед поданням.
- Не показуйте фото, відео чи голоси дітей до 18 років.

## 10. Обмеження та ідеї

Марсіанська погода це навчальна модель (живого каналу погоди Марса немає: сервіс InSight завершив роботу, а дані Perseverance MEDA не є простим веб-API). Офлайн-режиму (PWA) немає. Автотестів інтерфейсу немає. Beta-переклади потребують перевірки носіями мови. Баланс гри це навчальна модель, а не інженерна симуляція.

## Марс і погода (оновлення)

Тепер 10 рівнів: 5 місячних і 5 марсіанських («Привіт, Марсе», «Крижані соли», «Сезон пилу», «Глобальна пилова буря», «Командир Марса»). На Марсі Сонце слабше (5-6 блоків замість 8), а небо щодня інше: ясне, холод (-1 блок, рослини ростуть гірше), пил (половина світла), пиловий вихор (чистить панелі: +2 блоки наступного дня), глобальна буря (чверть світла). Гравець бачить погоду сьогодні й завтра на картці «Погода на Марсі», весь прогноз місії на екрані «Вступ», а небо анімується на фото. Щит на Марсі має бути на 5 пунктів міцнішим (тонке повітря). Питань тепер 39 (12 місячних, 15 марсіанських, 12 загальних), без повторів у межах рівня; рішень 9. Джерела з позначкою `verify` у `sources.extra.ts` треба звірити з точною сторінкою NASA перед поданням.
